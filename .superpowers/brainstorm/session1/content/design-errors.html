Design: Error Handling & Testing

Section 4 of 4 — every failure state handled gracefully

⚠️ Error States & User Messages
Error What user sees What happens
No mic permission "Please allow microphone access" Browser prompt + guide shown
Audio too short (<1s) "Recording too short — try again" Client-side check, no API call
Bhashini down Spinner → silently falls back Auto-retry with Groq, badge shows engine used
Groq quota hit Spinner → silently falls back Auto-retry with Python function
All engines fail "Transcription failed — please try again" Toast error, audio preserved for retry
Gemini correction fails Raw transcript shown, no error Silently skip correction, log error
Offline / no internet "You're offline — connect and retry" navigator.onLine check before API call
Recording >5 min Auto-stops + warning at 4:45 Netlify function 26s timeout respected
🎯 Accuracy Improvement Techniques
Language hint injection
Pass language code to every engine. Whisper performs 30–40% better with explicit language vs auto-detect.
Audio pre-processing
Client-side noise gate via Web Audio API. Trim leading/trailing silence. Normalize volume before upload.
Gemini correction prompt
Language-aware prompt: fixes Devanagari/Tamil script, handles code-mixed speech (Hinglish, Tanglish), adds punctuation.
User-editable output
Text preview is editable. Users fix errors before downloading — crowdsources implicit feedback for future improvement.
🧪 Testing Strategy
Unit Tests (Vitest)
Fallback logic, language mapping, export formatters (docx/pdf/srt), Zustand store actions
Integration Tests
Netlify Function handler with mocked API responses for all 3 engines + Gemini correction path
E2E Tests (Playwright)
Record → transcribe → copy flow. Auth flow (login/logout). Download each format. Mobile viewport tests.
