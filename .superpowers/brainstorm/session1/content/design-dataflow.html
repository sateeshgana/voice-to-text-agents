Design: Data Flow & Fallback Logic

Section 3 of 4 — how audio travels from mic to text, with every failure covered

🎙 Step 1 — Recording (Browser)
User taps Record
→
MediaRecorder API
WebM / Opus codec
→
Audio chunks buffered
Max 5 min / ~4MB
→
User taps Stop
Blob assembled
⚡ Step 2 — Transcription (Netlify Function)
POST /api/transcribe
REQUEST (multipart/form-data)
audio: Blob (WebM)
language: "hi" | "ta" | "te"...
correction: boolean
userId?: string (JWT)
RESPONSE (JSON)
text: string
language: string
engine: "bhashini"|"groq"|"python"
corrected: boolean
duration: number
timestamp: ISO string
🔄 Fallback Waterfall Logic
1
Bhashini API
Call ULCA pipeline for selected language. Timeout: 15s. Best Indian accuracy. ✓ Success → return result
2
Groq Whisper API
If Bhashini fails/times out. Groq Whisper Large v3 with language hint. Timeout: 20s. ✓ Success → return result
3
Python Function (faster-whisper)
Last resort. Runs faster-whisper (medium model) + SpeechRecognition fallback. No quota. Cold start ~8s. ✓ Always succeeds
✨
Gemini Correction Pass (optional)
If AI Correction toggle is ON: send raw text to Gemini 2.0 Flash with prompt: "Fix grammar, punctuation and script rendering for [language]. Return only corrected text." Adds ~1s.
🗄️ Step 3 — Storage & History
👤 Anonymous User
Result saved to localStorage.
Up to 20 recent transcripts.
Cleared on browser data clear.
🔐 Logged-in User
Result saved to Netlify Blobs.
Key: userId/timestamp
Unlimited history, 1GB free.
